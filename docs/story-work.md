# 허들링 앱 — 디자인 작업 흐름

> 이 문서는 "내가 실제로 어떻게 작업하는지"를 적는다. "무엇을 위한 일인지"는 `docs/story-service.md`에 있으며, 두 문서는 섞지 않는다.
> 출처: AI 없이 손으로 작업했던 마지막 경험 (사용자 진술)

## 작업 흐름

| # | 단계 | 산출물 | → 넘김 (에이전트 경계) |
|---|---|---|---|
| 1 | 레퍼런스 수집 | 경쟁사 레퍼런스 모음 | 나 → **uibowl** |
| 2 | 분석·반영 포인트 추출 | 분석 내용 / 반영할 부분 목록 (Figma) | 혼자 함 |
| 🚦 | **G1. 이 정도 모으면 충분한가?** | | 나에게 확인 |
| 3 | 화면 설계 구체화 | 화면 설계 문서 | 혼자 함 |
| 🚦 | **G2. 이 규칙(화면 설계)으로 확정해도 되나?** | | 나에게 확인 |

| 🚦 | **G3. 컨셉 시안을 확정해도 되나?** (5번 협의) | 확정된 컨셉 시안 | 나 ↔ **내부 관계자** |
| 6a | 토큰·컴포넌트 제작 | 디자인 토큰, 컴포넌트 (Figma) | 나 → **Figma** |
| 🚦 | **G4. 이 규칙(토큰·컴포넌트)으로 확정해도 되나?** | | 나에게 확인 |

| 7 | 가이드 위반 검토 | 검토 결과 | ⏳ 가이드는 나중에 받는다 |

## 게이트 규칙

- 모든 게이트에서 작업자는 멈추고, 확인을 받은 뒤에만 다음 단계로 넘어간다.
- G3은 **내부 관계자**가 확인하고, 나머지 게이트는 모두 **나(사용자)**가 확인한다.

## 미결 사항

1. **7번 검토 기준(우리 가이드)은 사용자가 나중에 준다.** 받기 전까지 7번 검토는 임의로 판단하지 않는다.
